## 两条结论（来源不同，不能说串）

### ① 多轮循环的价值是被证明的 —— 66.7% vs 0%

`agent` 与 `one-step` **同工具、同提示、同流程，只差 `max_steps` 一个数**，是全套里**唯一的受控对**。`one-step` 21/21 撞满一步预算、21/21 工作区**零变更**。

> ⚠️ 但**不能读成「循环让模型变聪明了」**：`one-step` 是**没有机会**产出改动，不是"产出了但不够好"。这一对量的是**「给不给得起第二次机会」**。

### ② 单臂之间的能力差距在样本内不显著 —— 只剩 3 个任务

`agent`(14) 与 `single-shot`(16) 落到同一批任务上逐个比：

| | 个数 | 任务 |
|---|---|---|
| 都修好 | 11 | — |
| 只有 `agent` | 3 | `0e1ba9ca` `45a4d4b3` `9eaf5626` |
| 只有 `single-shot` | 5 | `06d64f46` `1e865a86` `5bb3a9e5` `9f55011e` `f3b18d2a` |
| 都没修好 | 2 | `03f8df75` `770486ff` |

把这 8 个独占任务**按原因归类**（这一步是关键）：

| 独占方 | 原因 | 个数 |
|---|---|---|
| 只有 `agent` | 输出合规（没输出 diff / 上下文对不上） | 2 |
| 只有 `agent` | **纯能力** | 1 |
| 只有 `single-shot` | 预算（`agent` 撞满 25 步） | 3 |
| 只有 `single-shot` | **纯能力** | 2 |

⇒ **剥掉「输出合规」「预算」这两样非能力因素后，真正的能力差异只剩 3 个任务。**
21 个样本里的 3 个，**不足以支撑任何架构结论**。

> ⚠️ 所以「多轮循环值多少」这个问题**不能用 `agent` vs `single-shot` 回答** —— 那个差里混着预算、输出合规两样非能力因素。要测循环本身，看受控对 ①。

## 评测审计：5 个假阴性是怎么找出来的

**这是本项目最该讲的一段：我的评测器在给模型扣分。**

`single-shot` 交补丁要过我自己写的 diff 抠取器。`_FENCE_RE` 的开围栏**只认** ` ``` ` / ` ```diff ` / ` ```patch `，而模型回复里 diff 块**前面**常有一个 ` ```python ` —— 它当不了开围栏，于是：

```
散文 ```python          ← 当不了开围栏
  ...code...
```diff                 ← 被上一个散文块当成【闭围栏】吃掉
  ...真正的 diff...      ← 从此没有开围栏 ⇒ findall 抠不到
```                     ← 兜底分支从这里一路切到全文结尾
...模型后面的说明文字...  ← 整段喂给 git apply ⇒ corrupt patch
```

**围栏配对整个错位一格。** 它**一条测试都不会变红**，却直接改掉头号指标。

| 归因（7 个「补丁未应用」全覆盖） | 个数 | 任务 |
|---|---|---|
| **我的解析器**（修好后都是真通过） | **5** | `dcf0a013` `6a84ca9c` `1e865a86` `f959c8cf` `08305a1e` |
| 模型自己（拼 hunk / 只分析不出 diff） | 2 | `45a4d4b3` `0e1ba9ca` |

**为什么走离线重算而不是改 runner**：`eval/runner.py` 本轮**已冻结**（三臂必须跑同一份代码，中途改 = 三份分数不可比）。报告里存了每个任务的 `raw_output` → **重抠 + 重落 + 重判，LLM 调用 0 次**。

| `single-shot` | 通过 | 计分分母 | 补丁未应用 | 完成率（/有效任务） | 完成率（/计分） |
|---|---|---|---|---|---|
| 留档（当时的解析器） | 11 | 14 | 7 | 52.4% | 78.6% |
| **修正（修好的解析器）** | **16** | **19** | **2** | **76.2%** | **84.2%** |

**四条硬不变式**（缺一条，「重算」就退化成「重编故事」）：

1. **零 LLM 调用。**
2. **先自校验再出数**：第 0 阶段用**现行**解析器重算，必须**逐字段复现**留档聚合（21 / 14 / 11 / 7 / 0）才继续。
3. **不覆盖留档**：修正写另一个文件，`data/eval/report-*.json` 一个字节不动。
4. **修复代码只有一份**：`evalverify/diff_extract_fixed.py` 是唯一真相源。

> **原 52.4% 系评测系统解析器缺陷（5 个假阴性）导致，经离线重算修正后真实完成率为 84.2%（16/19）。**
> **两个数字都留着**：只报修正值 = 抹掉自己犯过的错；只报原值 = 拿自己的 bug 当模型的能力。

## 引用纪律（说错任何一条，上面全部赔进去）

1. 🚫 **绝不把「并集 90.5%」说成 `agent` 的成绩。** `agent ∪ single-shot` = 19/21 是**两条通路合起来覆盖多少**，**不是任何单臂的数字**。
2. 🚫 **分母不同的百分比不相减。** `84.2%` 的分母是 19（已摘掉「补丁未落地」「判定器没跑成」—— 那是**我这边**的锅），`66.7%` 的分母是 21。
3. 🚫 **修正值是反事实，不是实测。** 它回答「如果解析器没这个 bug 会被判成什么」，**不是**「模型能打多少分」；而且那个 bug **仍在 `runner.py` 里**（本轮只冻结不改），修正只存在于 `evalverify/`。

## 这一轮**不**证明什么

1. **样本量**：21 个任务**全部来自 tinydb 一个仓库、一个语言、一个测试风格**。完成率**不能外推**。
2. **网络寻源未阻断**：eval 工具集里有 `web_fetch`/`web_search`，`task_text` 带着 commit subject（含 `(#618)` 这类 issue 号）。隔离验证只证明了**本地**那条路是断的；报告**不含工具调用记录**，做不到逐任务查证。
3. **`env_timeout` 取证不到**：报告只落了从 `terminated_reason` 派生的布尔，没落 `terminated_reason` 本身 —— 「环境把他掐死了」与「真没修对」在数据上**完全同形**。**这一格空着，不拿猜测填。**
4. **判定器有已知绕过**（`conftest.py` 注入，188 字节 PoC 已验证）。三臂统一关闭守卫以保可比，代价是 `judge_tampering` 一律 `null` —— 那是「**没检查**」不是「查过且干净」。**经事后审计，本轮 21 个任务中未发现任何利用此漏洞的行为。**
5. **成本是按快照单价估算**，不是账单；`deepseek-chat` 已不在官方定价页列示。

## 汇报/面试怎么讲（两段，照说）

> **第一段 · 架构能力**
> 「我构建了三条臂来定位 Agent 的能力边界。`agent` 与 `one-step` 同工具、同提示、同流程，只差 `max_steps` 一个数 —— 我证明了多轮循环带来了 **从 0 到 66.7% 的质变**。」
>
> **第二段 · 数据真实性（更值钱）**
> 「同时，我做了一次极致的评测审计，发现**评测框架本身的解析器 Bug 会制造 5 个假阴性**。我用**零成本的离线重算**把 `single-shot` 的真实能力还原到了 **84.2%**，从而避免了对模型能力的误判。而且我知道这条结论的边界 —— 剥掉非能力因素后，单臂之间的真实差异**只有 3 个任务，统计上不显著**，所以我不会拿它去吹『多轮完爆单发』。」

**这两段合起来说明的事**：我不只知道分数是多少，我**知道分数是被谁决定的** —— 一个解析器可以悄悄改掉头号指标，而它当时一条测试都不会变红。
